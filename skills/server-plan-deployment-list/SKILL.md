# 服务器规划 - 生成部署清单

根据已分析出的应用清单，生成标准化的服务器部署清单。这是服务器规划流程的第二步。

## 工作流程

### Step 1: 获取应用清单

输入来源：
- 直接来自 `server-plan-app-analysis` 的分析结果
- 用户提供的应用列表
- 读取参考文件 `references/deployment-rules.md` 获取合并与部署规则

### Step 2: 应用合并（关键步骤）

按以下优先级合并应用到同一台服务器：

**合并原则：**

1. **"共享部署"的应用**：直接共用，如 nginx、redis、RabbitMQ
2. **"混合部署"的应用**：按以下优先级合并
   - 优先级1：同产品的多个组件合并（如电子商城的4个服务）
   - 优先级2：不同产品间功能相关的应用合并
   - 合并后预计资源不能超出服务器实际配置
3. **"独立部署"的应用**：必须独占一台服务器

**基础设施合并规则：**

| 类别 | 合并策略 | 备注 |
|------|---------|------|
| Redis | 所有产品共用1套（面客端独立） | 按DBIndex隔离 |
| Nginx | 所有产品共用1组 | 按产品分配置 |
| RabbitMQ | 所有产品共用1套 | 按vhost隔离 |
| Java支撑服务(业务) | 交易/招标文件制作/电子合同共用 | - |
| Java支撑服务(评标) | 评标/开标/交易共用 | - |
| Windows支撑服务 | 必须独立 | 不可混合 |
| Ecloud平台 | 独立部署 | 几乎所有项目需要 |
| 数据库 | 尽量分库隔离 | 业务/开评标/其他分开 |
| 文件存储(NFS) | 共用1套 | 注意目录区分 |

### Step 3: 资源配置计算

对每台服务器计算最终配置：

1. **基础配置**：取合并应用中的最大CPU/内存需求
2. **叠加规则**：
   - 多个高CPU应用同台 → CPU取最大值 × 1.5
   - 多个高内存应用同台 → 内存累加 × 0.8
   - 磁盘按需累加
3. **集群化考量**：
   - 面客端应用（开标大厅、会员端等）→ 集群部署2台+
   - 后台管理类 → 单台即可
4. **动态测算**（如有性能基线）：
   - 在线用户数 → 应用服务器台数
   - 同时评标标段数 → 评标服务器台数

**标准配置参考（无性能基线时）：**
- 小型项目（<50标段/月）：8C16G 标配
- 中型项目（50-200标段/月）：8C16G~16C32G
- 大型项目（>200标段/月）：需性能测算

### Step 4: 生成服务器清单

按以下分类输出服务器：

1. **PaaS平台** - Ecloud、Docker仓库
2. **应用服务器** - 各业务应用
3. **中间件服务器** - Redis、Nginx、RabbitMQ
4. **数据库服务器** - MySQL/达梦等
5. **文件服务器** - NFS存储、备份
6. **GPU服务器**（如有AI需求）

### Step 5: 输出部署清单

#### 方案A: 输出为 Excel 文件

使用 openpyxl 生成标准格式的 Excel 部署清单。

参考 `references/output-template.md` 了解输出格式。

#### 方案B: 输出为 Markdown 表格

```markdown
## 服务器部署清单

### 正式环境

| 序号 | 分类 | 服务器用途 | 操作系统 | 资源类型 | CPU | 内存(G) | 磁盘(G) | 端口 | 部署要求 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | PaaS平台 | eCloud、Docker仓库 | centos7.9 | 虚拟机 | 8 | 16 | 300 | 8080,5044,443,3690 | 独立 |
| 2 | 交易系统 | 中心端、统一认证、竞价 | centos7.9 | 虚拟机 | 8 | 16 | 200 | 8080~8083 | 独立 |
| ... | ... | ... | ... | ... | ... | ... | ... | ... | ... |

### 测试环境
（正式环境资源减半）
```

### Step 6: 补充说明

输出清单后，补充以下信息：
1. **资源汇总**：总vCPU、总内存、总磁盘
2. **物理机换算**（如需要）：虚拟化比例3:1
3. **注意事项**：国产化、网络策略、安全设备等
4. **专属硬件**：推流管理机、语音一体机等（如涉及不见面开标）

## 注意事项

1. **测试环境**：资源一般为正式环境的50%
2. **集群部署**：面客端应用（开标大厅、竞价、会员端）建议至少2台
3. **Windows服务器**：必须独立，配置一般4C8G
4. **国产化适配**：ARM内核CPU数量翻倍
5. **端口规划**：同一服务器上不同应用端口不能冲突
6. **IOPS要求**：
   - 应用服务器 ≥ 500
   - 中间件服务器 ≥ 1000
   - 数据库服务器 ≥ 5000
