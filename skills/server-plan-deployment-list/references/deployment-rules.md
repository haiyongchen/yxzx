# 部署合并规则

## 部署类型定义

| 类型 | 含义 | 操作 |
|------|------|------|
| 独立部署 | 独占一台服务器 | 不与其他应用合并 |
| 共享部署 | 共用同一应用实例 | 如nginx、redis，所有产品共用 |
| 混合部署 | 可与其他应用同台 | 按优先级合并 |

## 混合部署合并优先级

### 优先级1：同产品合并
同产品的多个"混合部署"组件优先合并到同一台服务器。

示例：
- 电子商城：EpointMall + EpointMallService + EpointMallAPI + EpointMallSync → 1台8C16G

### 优先级2：跨产品合并
不同产品间功能相关、负载互补的应用可合并。

示例：
- 数据交换抽取服务 + 前置服务 → 1台
- 大数据平台 + 集成开发平台管理端 → 1台

### 合并上限
- 合并后CPU不超过16C（虚拟机）
- 合并后内存不超过32G
- 超出则拆分到多台

## 基础设施合并详细规则

### Redis
- 默认所有产品共用1套Redis
- 按DBIndex隔离不同产品数据
- 面客端应用（网站、竞价、不见面开标）建议单独部署
- 配置：4C8G起步，每10个接入应用加倍

### Nginx
- 所有产品共用1组Nginx
- 按产品分组配置反向代理
- 配置：4C4G起步，每20个接入应用加倍
- 省级项目建议网站nginx与其他分开

### RabbitMQ
- 所有产品共用1套RabbitMQ
- 按vhost隔离不同产品消息
- 配置：4C8G起步，每10个接入应用加倍

### Java支撑服务(业务) - ZtbFileWebServerJava
- 与业务应用混合部署，不与中间件（nginx/redis/rabbitmq）同台
- 配置：2C2G（仅占2G内存）
- 可与中心端、会员端、接口服务等业务应用共存于同一台服务器

### Java支撑服务(评标) - ZtbFileWebServerJava
- 评标系统、不见面开标共用
- 配置：8C16G（解密时段CPU高）

### Windows框架支撑服务
- 必须独立部署
- 配置：4C8G
- 需要Windows Server 2016/2019

### Ecloud平台
- 独立部署，不与其他混合
- 配置：8C16G，1T磁盘
- 几乎所有项目都需要（除非客户已有）

### 数据库
- 按业务、开评标、其他三个维度分库
- 共用数据库服务器，但使用不同表空间
- 配置：16C32G起步
- 建议物理机+PCIe SSD

### 文件存储(NFS)
- 所有产品共用1套
- 注意区分不同存储目录
- 配置：4C8G，容量按需

## 集群部署规则

以下应用建议集群部署（至少2台）：
- 不见面开标大厅（BidOpening）
- 会员端（TPBidder）
- 竞价系统（EpointBid_JingJia）
- 评标系统（TPPingBiao）- 根据标段数量确定

以下应用单台即可：
- 中心端管理（TPFrame）
- 后台管理类应用
- 基础服务

## 特殊规则

1. **版本兼容**：评标系统8.0.52.0以上已集成智能评标，无需单独部署
2. **国产化**：ARM内核CPU数量翻倍
3. **GPU需求**：AI评标、智能编制等需要GPU服务器
4. **外网访问**：部分应用需映射外网（竞价、开标、CA网办等）
5. **安全隔离**：应用与数据库间如通过安全设备需保持长连接

## 已落地项目合并经验

### 小型项目（约13台正式，4台测试）
- 业务合并：认证+中心端+Java业务(2G) 同台 / 会员端+文件制作+Java业务(2G) 同台 / 接口+调度 同台
- 开评标合并：评标+清标+开标 同台
- 中间件合并：nginx+redis+rabbitmq 同台（不含Java业务）
- 测试环境：3~4台，全部业务合并

### 中型项目（约22台正式，5台测试）
- 每个主要应用独立部署
- 中间件可合并
- 测试环境：4~5台，按业务/开评标/门户网站分组合并

### 大型项目（约33台正式，6台测试）
- 每个应用完全独立
- 含电子档案、移动端、串通投标等扩展产品
- 测试环境：6台

### 配置参考范围
- ecloud：8C16G（固定）
- 竞价系统：8C16G（CPU/内存要求高）
- 评标Java支撑：8C16G（CPU高）
- 数据库：8C16G ~ 16C32G
- 其他应用：4C8G
- 国产化时CPU翻倍
