# Skill Evolver - 技能自进化引擎

自动识别可复用的工作流并沉淀为 Skill，实现 Agent 能力的持续自我进化。

## 核心能力

| 能力 | 用途 |
|------|------|
| **评估** | 判断任务是否值得沉淀为 Skill |
| **创建** | 生成符合规范的 SKILL.md 文件 |
| **检查** | 质量检查清单确保 Skill 可用 |
| **去重** | 避免创建重复或相似的 Skill |
| **更新** | 迭代优化已有 Skill |

---

## 1. 评估标准 (Evaluation Criteria)

### 必须满足 (MUST)
- [ ] 工具调用次数 ≥ 5
- [ ] 任务成功完成
- [ ] 包含可复用的流程/模式

### 建议满足 (SHOULD)
- [ ] 涉及多个文件或系统交互
- [ ] 包含非显而易见的技巧
- [ ] 有明确的输入/输出边界
- [ ] 用户明确表达复用意愿

### 加分项 (NICE TO HAVE)
- [ ] 包含错误处理/边界情况
- [ ] 有具体的配置参数
- [ ] 跨项目/跨场景适用
- [ ] 节省未来 >50% 的时间

### 不沉淀的情况
- 一次性任务（如特定数据的单次处理）
- 过于简单的操作（如单文件读取）
- 高度依赖特定上下文的内容
- 已有高度相似的 Skill 存在

## 2. 沉淀流程 (Extraction Workflow)

### Step 1: 触发检测
任务完成后，检查：
```
工具调用数 ≥ 5 ? → 进入评估
用户说"保存这个"? → 进入评估
```

### Step 2: 快速评估
回答以下问题：
1. 这个流程在类似场景下会重复出现吗？
2. 下次遇到类似问题，这个 Skill 能节省多少时间？
3. 是否有非显而易见的技巧需要记录？
4. 能否脱离当前上下文独立使用？

**评分**：
- 4个"是" → 立即沉淀
- 3个"是" → 建议沉淀
- ≤2个"是" → 暂不沉淀，记录到日志

### Step 3: 命名规范

**Skill 命名规则**：
- 全小写，单词间用连字符 `-`
- 格式：`<domain>-<action>` 或 `<domain>-<target>-<action>`
- 避免冗余词汇（如 "skill", "helper", "utils"）

**示例**：
```
✅ feishu-doc          ✅ tencent-docs
✅ e-trading-report    ✅ qq-email-sender
❌ FeishuSkill         ❌ report-generator-tool
```

### Step 4: 去重检查

创建前检查是否已存在相似 Skill：

```bash
# 搜索关键词
grep -r "关键词" skills/*/SKILL.md

# 检查功能重叠
# 阅读相似 Skill 的 description 确认是否重复
```

**去重标准**：
- 功能重叠 > 70% → 更新现有 Skill，不创建新的
- 功能重叠 30-70% → 创建子 Skill 或扩展现有
- 功能重叠 < 30% → 创建新 Skill

### Step 6: 质量检查

创建后执行以下检查：

```markdown
## 质量检查清单

### 结构检查
- [ ] 包含 YAML frontmatter (name, description, metadata)
- [ ] name 与文件夹名一致
- [ ] 有清晰的标题和章节
- [ ] 无 README.md 冲突文件

### 内容检查
- [ ] description 包含触发条件
- [ ] 有明确的输入/输出定义
- [ ] 步骤可执行、无歧义
- [ ] 包含至少1个示例
- [ ] 错误处理场景已覆盖

### 技术检查
- [ ] 无硬编码的敏感信息
- [ ] 路径使用相对路径或占位符
- [ ] 命令可在目标环境执行
- [ ] 无过时的 API 或工具引用

### 可读性检查
- [ ] 语言简洁，无冗余
- [ ] 使用表格/列表提升可读性
- [ ] 专业术语已解释
- [ ] 格式统一（标点、大小写）
```

## 3. 更新已有 Skill

### 触发条件
- 发现 Skill 有 bug 或过时内容
- 用户反馈 Skill 需要改进
- 使用 Skill 时发现缺失场景

### 更新流程
1. 读取现有 SKILL.md
2. 识别需要更新的部分
3. 更新内容并增加版本号
4. 在变更日志中记录
5. 重新执行质量检查

### 版本号规则
- **Major**: 破坏性变更（接口改变、移除功能）
- **Minor**: 功能新增（向后兼容）
- **Patch**: Bug 修复、文档更新

## 4. 每日回顾任务

### 回顾流程
1. 读取当天的 `memory/YYYY-MM-DD.md`
2. 识别所有涉及 ≥5 步工具调用的任务
3. 检查是否已记录到 `skill-evolution-log.md`
4. 对未记录的任务执行评估
5. 对符合条件的任务执行沉淀流程

### 输出报告
```markdown
# Skill Evolution Daily Report - YYYY-MM-DD

## 统计
- 今日复杂任务数: {N}
- 已沉淀为 Skill: {N}
- 记录为候选: {N}
- 暂不沉淀: {N}

## 新增 Skill
1. **{skill-name}** - {简述}

## 候选任务（待评估）
1. **{任务简述}** - {理由}

## 建议
{对 Skill 管理的建议}
```

```bash
mkdir -p skills/{skill-name}

grep -r "关键词" skills/*/SKILL.md

# 统计今日工具调用
# （从对话历史中提取）

# 查看 Skill 列表
ls skills/
```

### 决策速查

| 场景 | 行动 |
|------|------|
| 工具调用 ≥ 5 且成功 | 评估是否沉淀 |
| 用户说"保存这个" | 立即评估 |
| 发现相似 Skill 存在 | 更新而非创建 |
| 任务失败但有学习价值 | 记录到 learnings |
| 一次性数据任务 | 不沉淀 |

---

## 6. 最佳实践

1. **及时沉淀**：任务完成后立即评估，趁记忆新鲜
2. **保持精简**：Skill 只包含必要信息，避免过度文档
3. **用户确认**：重大 Skill 创建前可征求用户意见
4. **定期回顾**：每周回顾候选列表，防止遗漏
5. **持续迭代**：Skill 不是一次性的，随使用不断优化
