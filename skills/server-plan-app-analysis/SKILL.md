# 服务器规划 - 应用分析

从建设方案/功能清单中分析出需要部署哪些应用，是服务器规划流程的第一步。

## 工作流程

### Step 1: 读取输入文档

输入可能是以下格式之一：
- **Word文档(.docx)**: 建设方案，包含功能模块描述、系统架构、建设内容章节
- **Excel文档(.xlsx/.xls)**: 功能清单，包含功能模块名称列表
- **纯文本**: 用户直接描述的建设内容

用 `read` 工具读取文档内容。如果是 Word，用 python-docx 提取段落；如果是 Excel，用 openpyxl 提取数据。

### Step 2: 提取建设范围中的产品/功能关键词

**⚠️ 核心原则：以章节目录（子目录）为准，不要从正文描述中推断产品！**

匹配方法：
1. **首先提取文档的目录结构**（Heading 1/2/3 或 toc 标记的章节）
2. **只根据目录标题匹配产品**，正文中的功能描述仅用于判断"选配"项
3. **如果某产品没有对应的独立章节目录，则不纳入部署范围**
4. 产品与章节目录的映射见下表

### Step 3: 加载标准产品应用库

读取参考文件 `references/product-app-catalog.md`，获取每个产品的完整应用清单，包括：
- 应用名称（中英文）
- 服务器类别
- 部署要求（独立/共享/混合）
- 最小化配置
- 是否选配及选配条件
- 推荐端口
- 部署方案说明

### Step 4: 逐产品匹配应用

对每个匹配到的产品，按以下规则筛选应用：

1. **"必须"项**：直接添加
2. **"选配"项**：根据建设方案中的功能描述判断是否需要
   - 如建设方案明确包含该功能 → 添加
   - 如不确定 → 列出并询问用户
3. **版本依赖项**：检查选配条件中的版本要求
   - 如"评标系统版本低于8.0.52.0时需要部署" → 需确认版本

### Step 5: 识别可共享的基础设施

以下基础组件可跨产品共用，合并去重：

**中间件类（共享部署）：**
- Redis缓存服务
- Nginx统一对外访问服务
- RabbitMQ消息队列服务

**基础服务类（共享部署）：**
- Java支撑服务(业务) - ZtbFileWebServerJava
- Java支撑服务(评标) - ZtbFileWebServerJava
- Windows框架支撑服务

**平台类（独立部署）：**
- Ecloud平台、Docker仓库（pass平台）

**数据库类（共享部署）：**
- 数据库服务（MySQL/达梦/人大金仓等）

**存储类（共享部署）：**
- 统一文件存储(NFS/File)
- 文件备份服务器

## 实际项目经验（从已落地项目提炼）

参考 `references/real-project-patterns.md` 获取已落地项目的部署模式和配置规律。

## 注意事项

1. **章节目录优先**：只根据目录标题匹配产品，正文描述仅用于判断选配项
2. **不要过度推断**：正文提到某功能不代表需要单独部署对应产品，要看是否有独立章节目录
3. **ecloud平台**：几乎所有项目都需要，独立部署 8C16G 起步
4. **数据库**：尽量按业务、开评标、其他隔离分库
5. **中间件**：小型项目可合并（nginx+redis+rabbitmq同台），中大型项目分离
6. **Windows支撑服务**：必须单独部署，不与其他混合
7. **存储目录**：注意区分 AttachStorage 和 EpointMisTempFile 等目录
8. **版本兼容**：部分应用在新版本中已集成（如智能评标在评标系统8.0.52.0以上已包含）
9. **国产化**：ARM内核CPU数量翻倍（如非国产4C → 国产8C）
10. **测试环境**：业务尽量合并，一般3-4台即可
11. **最小内存**：每个应用最低2G内存，评标Java支撑建议8G
