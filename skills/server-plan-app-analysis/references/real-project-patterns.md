# 已落地项目部署模式参考

> 从10+个已落地项目的服务器规划中提炼的规律

## 一、标准部署模式（正式环境）

### 基础设施层（固定）
| 服务器 | 配置 | 说明 |
|---|---|---|
| eCloud平台 | 8C16G / 16C16G | 独立部署，不与其他混合 |
| 数据库 | 8C16G ~ 16C32G | 建议物理机+SSD |
| 文件服务器 | 4C8G ~ 8C16G | NFS共享存储 |
| 文件备份 | 4C8G ~ 8C16G | rsync备份 |

### 中间件层（可合并可分离）
| 模式 | 适用场景 | 配置 |
|---|---|---|
| 合并模式（小型项目） | nginx+redis+rabbitmq 同台 | 4C8G |
| 分离模式（中大型项目） | nginx独立 / redis独立 / rabbitmq独立 | 各4C8G |

### 应用层（按产品分组）
| 分组 | 典型应用 | 配置范围 |
|---|---|---|
| 业务系统 | 中心端+认证+会员端+接口+调度 | 4C8G ~ 8C16G，可合并2-3台 |
| 竞价系统 | 竞价系统+竞价服务 | 8C16G（CPU/内存要求高） |
| 开评标系统 | 评标+清标+开标大厅 | 4C8G ~ 8C16G |
| 门户网站 | 前台+后台+生成+ES | 4C8G ~ 8C16G，ES需500G磁盘 |
| 招标文件制作 | BSTool | 4C8G |
| 保证金 | 保证金平台 | 4C8G |
| 框架支撑 | Java支撑(业务) | 2C2G，与业务应用混搭，不与中间件同台 |
| 框架支撑 | Java支撑(评标) | 8C16G（CPU高） |
| 框架支撑 | Windows支撑 | 4C8G，独立Windows服务器 |

## 二、测试环境合并策略

测试环境一般 3~4 台：

| 台号 | 合并内容 | 配置 |
|---|---|---|
| 1 | eCloud平台 | 4C8G ~ 8C16G |
| 2 | 业务合并（认证+中心端+会员端+接口+调度+竞价+文件制作） | 4C8G ~ 8C16G |
| 3 | 开评标合并（评标+清标+开标+Java支撑评标） | 4C8G ~ 8C16G |
| 4 | 数据库+中间件合并 | 4C8G ~ 8C16G |

## 三、国产化配置翻倍规则

非国产 → 国产（ARM内核）时：
- CPU 翻倍：4C → 8C，8C → 16C
- 内存一般保持不变或适当增加
- 操作系统：中标麒麟7.2+ 或 openEuler
- 中间件：Tomcat → Tongweb（国产化时）

## 四、项目规模与配置对照

| 规模 | 正式环境台数 | 测试环境台数 | 典型CPU范围 | 典型内存范围 |
|---|---|---|---|---|
| 小型（限额以下） | 10~14台 | 3~4台 | 4C~8C | 8G~16G |
| 中型（招采平台） | 15~25台 | 4~6台 | 8C~16C | 8G~16G |
| 大型（综合平台） | 25~40台 | 6~10台 | 8C~24C | 16G~24G |

## 五、特殊硬件需求

部分项目需要专属硬件：
- **语音一体机**：专家抽取通知，Windows系统，4C8G
- **推流管理机**：不见面开标视频推流
- **视频会议服务器**：远程异地评标
- **GPU服务器**：AI搜索优化、智能编制

## 六、常见合并模式（已验证）

### 小型项目合并（安阳/公安局模式，约13台正式）
1. eCloud 8C16G
2. 认证+中心端+Java业务(2G) 8C16G
3. 会员端+文件制作+Java业务(2G) 8C16G
4. 接口+调度 8C16G
5. 评标+清标+开标 8C16G
6. 门户网站(前台+后台+ES) 8C16G + 8C16G
7. Java支撑(评标) 8C16G
8. Windows支撑 4C8G
9. 中间件(nginx+redis+rabbitmq) 4C8G
10. 数据库 8C16G
11. 文件存储 4C8G
12. 文件备份 4C8G

### 中型项目分离（北科院/盐城港模式，约22台正式）
每个主要应用独立部署，中间件可合并。

### 大型项目（兵团V1模式，约33台正式）
每个应用完全独立，含电子档案、移动端、串通投标等扩展产品。
