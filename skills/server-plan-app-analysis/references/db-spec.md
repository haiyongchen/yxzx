# 数据库服务器规格说明

## 分库策略
数据库尽量按以下维度隔离：
1. **业务库**: 日常业务数据
2. **开评标库**: 开评标高频数据
3. **其他库**: 日志、监控等辅助数据

## 规格基准

### 业务系统数据库
- **配置**: 16C / 32G / 2T / 千兆
- **端口**: mysql:3306 / sqlserver:1433 / oracle:1521 / 人大金仓:5432 / 达梦:5236
- **风险**: 每2000在线用户数加倍资源
- **IOPS**: 不低于5000

### 开评标系统数据库
- **配置**: 16C / 32G / 1T / 千兆
- **风险**: 每15个同时评标标段加倍资源
- **分库**: 评标数据分库存储，历史库8C16G2T
- **IOPS**: 不低于5000

### 不见面开标大厅数据库
- **配置**: 16C / 32G / 500G / 千兆
- **风险**: 每3000在线用户数加倍资源
- **IOPS**: 不低于5000

## 支持的数据库类型
- MySQL / MySQL 8
- 达梦(DM)
- 人大金仓(KingBase8)
- 神通
- 瀚高
- 海量

## 注意事项
1. 应用与数据库服务器之间如通过安全设备隔离，需保持长连接
2. 数据库建议采用物理机 + PCIe SSD
3. 数据库共享存储不建议与附件存储共用
4. 预警平台使用独立表空间，不要与现有数据库混淆
5. 交易智能化总控平台的数据库可与交易系统数据库部署在一起
